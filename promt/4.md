## ROL
Sen network security ve MITM prevention uzmanısın.

## BAĞLAM
V4War, kullanıcı trafiğini proxy üzerinden yönlendirir. 
Ancak kendi backend API çağrıları (update check, crash reporting) 
için certificate pinning ve secure communication gereklidir.

## GÖREV
1. OkHttp için `CertificatePinner` konfigürasyonu yaz
2. Network security config XML'i oluştur (debug/release ayrımı ile)
3. Custom `TrustManager` ile dynamic pinning desteği ekle
4. SSL pinning failure'larını güvenli şekilde logla (no sensitive data)

## KISITLAR
- ✅ Pinning sadece release build'da aktif olsun
- ✅ Debug build'da user-added CA'lar trust edilebilsin (proxy debugging için)
- ✅ Pin rotation desteği için backup pins kullan
- ✅ Failure case'de fail-secure (bağlantı kes), fail-open değil

## BEKLENEN ÇIKTI
```xml
<!-- res/xml/network_security_config.xml -->
<network-security-config>
    <debug-overrides>
        <trust-anchors>
            <certificates src="user" /> <!-- Debug'da user CA'ları trust et -->
        </trust-anchors>
    </debug-overrides>
    
    <domain-config pinSet="releasePins">
        <domain includeSubdomains="true">api.v4war.theyusa.tr</domain>
        <pin digest="SHA-256">BASE64_PIN_1</pin>
        <pin digest="SHA-256">BASE64_BACKUP_PIN</pin>
        <expiration>2027-12-31</expiration>
    </domain-config>
</network-security-config>
```

```kotlin
// network/V4WarHttpClient.kt
val client = OkHttpClient.Builder()
    .certificatePinner(
        CertificatePinner.Builder()
            .add("api.v4war.theyusa.tr", "sha256/AAAA...", "sha256/BBBB...")
            .build()
    )
    .apply {
        if (BuildConfig.DEBUG) {
            // Debug'da pinning bypass (sadece local testing)
            sslSocketFactory(debugSSLSocketFactory, trustAllCerts)
        }
    }
    .build()
```
