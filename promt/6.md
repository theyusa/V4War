## ROL
Sen plugin architecture ve extensibility design uzmanısın.

## BAĞLAM
V4War, yeni proxy protokolleri (hysteria2, tuic, shadowsocks-2022) 
için plugin desteği sunmalı. Mevcut yapı:
- `plugin/` klasörü var ama contract tanımlı değil
- `make plugin=xyz` ile build ediliyor ama runtime discovery yok
- Plugin'lerin core ile iletişimi FFI üzerinden, type-safe değil

## GÖREV
1. `V4WarPlugin` interface'ini tasarla (Kotlin + Go FFI compatible)
2. Plugin manifest schema'sı oluştur (JSON/Proto)
3. Runtime plugin loading ve version compatibility check ekle
4. Plugin sandboxing için permission model'i tanımla

## KISITLAR
- ✅ Interface, hem Kotlin hem Go tarafında implemente edilebilsin
- ✅ Plugin'ler isolated classloader ile load edilsin (Android)
- ✅ Manifest'te: name, version, protocol, permissions, entryPoint
- ✅ Core, plugin'e sadece whitelisted API'leri expose etsin
- ❌ Plugin, core'un private member'larına erişemesin

## BEKLENEN ÇIKTI
```kotlin
// plugin/api/V4WarPlugin.kt
@JvmDefaultWithCompatibility
interface V4WarPlugin {
    val manifest: PluginManifest
    fun initialize(context: PluginContext): Result<Unit>
    fun createHandler(config: PluginConfig): ProxyHandler?
    fun shutdown(): Result<Unit>
}

data class PluginManifest(
    val id: String, // reverse domain: tr.theyusa.plugin.hysteria2
    val version: SemVer,
    val protocol: String,
    val minCoreVersion: SemVer,
    val permissions: Set<PluginPermission> // NETWORK, STORAGE, etc.
)

// plugin/loader/PluginManager.kt
class PluginManager(
    private val coreApi: CoreApiProvider, // whitelisted API
    private val classLoaderFactory: ClassLoaderFactory
) {
    fun load(pluginPath: String): Result<V4WarPlugin>
    fun validateCompatibility(plugin: V4WarPlugin, coreVersion: SemVer): Boolean
    fun unload(pluginId: String): Boolean
}
```
